# Master Parking

A native Unity 6 port of the 18-level browser parking game in
`park_game (1).html`. The original file is left untouched; this project contains
the migrated level data, a reconstructed vehicle, and a touch-first Unity
runtime.

## Current status

Implemented and statically verified:

- 18 levels migrated from the source game, including walls, parked cars, cones,
  movers, road paint, signs, trees, lamps, gates and parking targets.
- P / R / D gears, steering wheel, gas and brake pedals, parking hold progress,
  crash and win states, star scoring, timers, restart, pause, level selection.
- Follow and overview camera modes with orbit/pan drag and crash shake.
- Main menu, level select, gameplay HUD, settings, results flow.
- Persistent unlocked level, stars, best times and settings through
  `ISaveStorage` (atomic file storage by default, PlayerPrefs alternative).
- Procedural audio and UI textures, so no bundled third-party art/audio is used.
- Android/iOS build menus, landscape player settings, safe-area-aware UI.

Still unverified:

- **Unity Editor is not installed on this machine.** The project has not been
  imported, the hand-authored scene has not been opened, and nothing has been
  run in Play Mode or on a device. The bootstrap menu is idempotent and repairs
  the scene if needed; run it first inside Unity.
- On-device 60 FPS, thermal behaviour and final mobile layout are not measured.

## Requirements

- Unity **6000.0.32f1** (Unity 6) with Android and/or iOS build support.
- No paid packages or external runtime dependencies.

## Open and run

1. Open the project folder in Unity Hub with Unity 6000.0.32f1.
2. Run **Master Parking → Setup → Prepare Project**.
   This creates the `Vehicle` and `Obstacle` layers, applies landscape/mobile
   player settings, imports `levels.json` into ScriptableObjects, creates or
   repairs `Assets/_Project/Scenes/Bootstrap.unity`, and adds it to Build
   Settings.
3. Open `Assets/_Project/Scenes/Bootstrap.unity` and press Play.
4. Optional: run the EditMode checks from **Window → General → Test Runner**.
   The assembly is `MasterParking.EditModeChecks`.

The scene only needs one GameObject with `AppRoot`. Everything else (camera,
vehicle, level geometry, UI, audio listener, EventSystem) is built at runtime.

## Controls

Touch:

- Drag the steering wheel to steer; release to let it return.
- Hold **GAS** / **BRAKE**.
- Tap **P**, **R** or **D** to change gear.
- Drag an empty part of the screen to orbit (follow) or pan (overview).
- Use the camera button to switch Follow/Overview; pause opens restart/menu.

Editor/development keyboard:

- `W` / `Up` gas, `S` / `Down` / `Space` brake, `A`/`D` or arrows steer.
- `1` Park, `2` Reverse, `3` Drive, `C` camera, `Esc` pause, `F2` restart.

Keyboard input is compiled only for the editor and development builds; shipping
mobile builds are touch-only.

`MasterParking.Core` has `noEngineReferences: true` and is tested independently.
The Unity layer adapts it; gameplay code never contains level-specific branches.

## Data-driven levels

- Canonical data: `Assets/_Project/Resources/Levels/levels.json`.
- Edit levels there, then run **Master Parking → Levels → Import JSON To
  ScriptableObjects** to regenerate `LevelCatalog.asset` and the per-level
  assets in `Assets/_Project/Levels/Generated/`.
- Adding or tuning a level requires no gameplay code changes.
- If the generated catalog is absent (fresh checkout), `LevelRepository` falls
  back to the JSON resource, so the project is still playable before import.
- The importer validates IDs, names, par times, targets and level geometry, and
  refuses to publish a catalog when validation fails.

## Vehicle and physics

The source game's SAT collision code was not ported. The player car uses a
deterministic kinematic simulation from `VehicleSimulation`, while Unity
colliders provide practical crash detection through
`Physics.OverlapBoxNonAlloc` against an `ObstacleRegistry`. Collision categories
map to the original Turkish crash messages (barrier, parked car, moving car,
traffic cone, out of bounds).

The car model is loaded at runtime from pre-triangulated OBJ payloads stored as
`.bytes` TextAssets and wrapped part metadata in
`Resources/Vehicles/vehicle-parts.json`. If a part is missing, a primitive
placeholder is used so gameplay still runs.

## Save data

`SaveManager` owns one `SaveData` document and writes through `ISaveStorage`:

- `FileSaveStorage` (default): atomic temp-file replace under
  `Application.persistentDataPath`.
- `PlayerPrefsSaveStorage`: alternative for platform key-value stores/tests.

Saved fields: unlocked level, per-level stars/best time/completion, last played
level, music/SFX/engine volumes, haptics and tutorial hints. Save writes happen
on completion, settings changes, app pause and quit.

## Build

- **Master Parking → Build → Android APK**: ARM64, IL2CPP, minimum API 24,
  landscape, application id `com.masterparking.game`.
- **Master Parking → Build → iOS Xcode Project**: produces `Builds/iOS`,
  minimum iOS 13, iPhone + iPad.
- Both menus run **Prepare Project** first, so levels and build settings are
  current.

Runtime also forces landscape auto-rotation on mobile and targets 60 FPS, as a
fallback if player settings are edited later.

## Asset provenance

- Level geometry, names, par times and gameplay tuning were extracted from the
  user-provided `park_game (1).html`.
- The vehicle parts were reconstructed from the embedded model in that file and
  are stored as OBJ-derived `.bytes` payloads.
- UI textures, gradients, signs and audio clips are generated procedurally at
  runtime. No paid or third-party runtime assets were added.
- The original HTML file was not modified.
